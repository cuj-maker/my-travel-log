# MY TRAVEL LOG

*Your Journey, Your Story, Your Archive.*

개인 여행 통합 관리 웹앱. 현재 **PHASE 1 (Foundation)** ·**PHASE 2 (항공·호텔·예약)**·**PHASE 3 (일정·지도·이동)**·**PHASE 4 (예산·지출·환율·정산)**·**PHASE 5 (아카이브)** 구현 완료.

## 실행 방법

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입체크 + 프로덕션 빌드
```

Node 18+ 필요. 데이터는 브라우저 localStorage(`my-travel-log:db:v1`)에 저장됩니다.

## 테스트 방법 (수동)

1. 처음 접속하면 SAMPLE 배지가 붙은 도쿄·방콕·파리 여행이 자동 등록됩니다. HOME의 통계·다가오는 여행·최근 기억·추천이 채워지는지 확인.
2. HOME › **새로운 여행 만들기** → 저장 후 새로고침해도 유지되는지 확인. 날짜 수만큼 빈 일정(Day)이 자동 생성됩니다.
3. 여행 상세에서 **수정**(날짜 변경 시 일정 일수 동기화) / **삭제**(연결 데이터 함께 삭제) 확인.
4. AI TRAVEL: 스타일·예산·월을 바꾸면 추천이 바뀌는지, “이 여행지로 여행 만들기”가 폼을 채워 주는지 확인.
5. MY PROFILE: 백업 다운로드 → 샘플 삭제 → 백업으로 복원, 외부 API 연결 상태(전부 미연결) 확인.
6. 모바일 폭(<1024px)에서 하단 탭 메뉴가 나타나는지 확인.

## Phase 2 테스트

1. FLIGHT & HOTEL에서 여행 선택 → **출국 항공권** 등록 → 해당 날짜 일정(PLANNER)에 출발·도착이 ‘예약 연동’으로 생기는지 확인.
2. 같은 구간에 항공편을 하나 더 등록하면 종합 점수·최저가·최단 비행 태그로 비교됩니다(가격만으로 순위 결정 안 함).
3. 숙소 등록 → 체크인·체크아웃이 일정에 생기고, 날짜가 겹치거나 귀국 전 체크아웃이면 경고가 뜹니다.
4. 예약 상태·결제 상태 변경, PDF/이미지 확인서 첨부(최대 1.5MB), 삭제 시 연동 일정 정리를 확인.
5. 이미 실행해 본 브라우저는 샘플 연동 데이터가 없으니 MY PROFILE에서 샘플 삭제 후 다시 불러오세요.

## Phase 3 테스트

1. TRAVEL PLANNER에서 여행·DAY 선택 → **장소 추가**(위도·경도를 넣으면 지도와 이동 계산에 포함). 저장된 장소 이름을 입력하면 자동완성으로 재사용할 수 있어요.
2. ▲▼로 순서 변경, 연필/휴지통으로 수정·삭제. 장소 사이의 이동수단을 바꾸면 거리·시간·교통비가 다시 계산됩니다(항상 ‘예상’ 표시).
3. **동선 최적화**: 예약 연동·예약 필요·시간이 정해진 식사는 고정, 나머지는 숙소 기준 가까운 순서로 빈 시간에 배치. 미리보기 후 적용.
4. 하루 이동시간·체류시간·교통비, 빡빡한 일정·휴무일·오픈 전 도착·이동 시간 부족 경고, 근처 추천(내 저장 장소), 비 오는 날 대체 확인.
5. TRAVEL BUDGET에서 일정 기준 예상 비용(장소+교통)이 반영되는지 확인. 항공·숙소를 바꾸면 이동 정보가 재계산됩니다.
6. 이미 실행한 브라우저는 새 샘플 좌표가 없으니 MY PROFILE에서 샘플 삭제 후 다시 불러오세요.

## Phase 4 테스트

1. TRAVEL BUDGET에서 여행 선택 → **예산 설정**으로 전체/1인/카테고리 예산 저장(카테고리 합계가 전체를 넘으면 막아요).
2. **지출 입력**: 외화를 고르면 샘플 환율이 채워지고(‘샘플’ 표시) 직접 고칠 수 있어요. 영수증 이미지/PDF 첨부, 결제자·공동/개인 구분.
3. 중복 방지: 결제 완료된 항공·호텔은 지출 내역에 ‘예약 결제분’으로 한 번만 집계되고, 같은 예약에 연결한 지출을 만들면 그 지출로만 집계됩니다. 미결제 예약은 ‘예약 미결제’로 따로 표시돼요.
4. 환율 탭에서 통화별 환율 저장, 정산 탭에서 동행자 등록 후 받을/보낼 금액과 송금 방법 확인.
5. 홈·여행 상세의 지출 합계도 같은 계산을 써요. 샘플을 다시 불러오려면 MY PROFILE에서 샘플 삭제 → 불러오기.

## Phase 5 테스트

1. 여행 상세 › **아카이브 · 사진 · 후기** (또는 ARCHIVE 메뉴) → **사진 업로드**: 여러 장 선택. JPEG에 위치(GPS)가 있고 방문 장소 300m 안이면 자동 연결, 촬영 시각도 읽어요. 사진을 눌러 설명·시각·장소 수정, 대표 사진 설정, 삭제.
2. 타임라인에서 장소 앞 체크로 방문 표시 → 사진·지출·장소 후기가 장소에 묶여 보여요.
3. 여행 전체 후기(별점·다시 가고 싶은 곳·아쉬운 점)와 장소·호텔·맛집 후기 작성.
4. **여행 종료** → 확인 창의 점검 안내(결제 전 예약, 방문 미표시 등) 확인 후 종료: 상태 Completed, 리포트 생성. 종료 후에도 모두 수정 가능하고 ‘리포트 다시 만들기’, ‘종료 취소’가 있어요.
5. MY PROFILE 백업은 사진까지 JSON 하나에 담아요(복원 시 사진도 복구).
6. 샘플 도쿄·방콕은 리포트가 포함돼 새로 불러와야 보여요: MY PROFILE에서 샘플 삭제 → 불러오기.

## 구조

```
src/
  types/models.ts      도메인 타입, 테이블 목록, Trip ID 캐스케이드 규칙
  db/                  database.ts(저장소 어댑터) · seed.ts · destinations.ts
  services/            tripService · recommendService (비즈니스 로직)
  integrations/        외부 API 슬롯 (항공·호텔·지도·교통·환율·날씨·LLM, 전부 미연결)
  components/          ui · layout · trip
  pages/               메뉴별 페이지
```

- 모든 행은 `tripId`로 연결되고, 샘플은 `isSample: true`로 구분합니다.
- 가격은 `priceSource`(sample/user/api)를 항상 표시합니다. 실시간 최저가라고 표기하지 않습니다.
- 저장소는 `db/database.ts` 한 곳에만 의존 → SQLite/Supabase 교체 지점.

## 알려진 한계

- 사진 파일은 IndexedDB에 저장(업로드 시 긴 변 1400px로 압축)돼 용량 여유가 크지만, 브라우저 데이터를 지우면 사라지니 백업하세요. 영수증·예약 확인서는 아직 localStorage(파일당 1.5MB 제한)예요. 동영상은 지원하지 않아요.
- 지도는 타일 없는 간이 좌표 지도, 장소 검색은 내 저장 장소 안에서만 동작합니다(지도·장소 API는 Phase 7). 교통비는 원화 기준의 대략적인 추정이라 나라별 요금과 다를 수 있어요.
- 샘플 여행지 이미지는 Unsplash 원격 URL이며 도시와 완벽히 일치하지 않을 수 있습니다.
- 데이터는 브라우저 단위로 저장되므로 정기적으로 백업하세요.
